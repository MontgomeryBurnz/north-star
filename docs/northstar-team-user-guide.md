# NorthStar Team User Guide

Daily operating guide for delivery teams, leaders, clients, and Admins

Last updated: June 27, 2026

## Purpose

NorthStar is an intelligence hub for complex program delivery. It helps teams keep program context, role updates, leadership input, delivery actions, artifacts, risks, decisions, and client-facing progress connected in one place.

NorthStar's product promise is simple:

> Where people, intelligence, and data move as one.

Use NorthStar daily to keep program signal current, understand what changed, and turn that signal into guided plans, team actions, work products, and executive visibility.

## Quick Start

1. Go to `https://www.north-star.live`.
2. Sign in with your NorthStar username and password.
3. Start with Quick Start if you are new or need a reminder of where each module fits.
4. Open Program Hub to set up a new program or manage an active program.
5. Use Guided Plans to understand what the team should do next.
6. Use Studio to create role-specific work products.
7. Use Leadership, Client Portal, or Admin only if your user type has access.

## Training Path

Use this path when onboarding a new user or team.

| Step | User action | Expected outcome |
|---|---|---|
| 1 | Sign in and review Quick Start. | User understands the core modules and where to begin. |
| 2 | Open Program Hub and select the correct client/program. | User works in the right program context before entering updates. |
| 3 | Confirm role focus. | User sees role-centric information first, especially when assigned to different roles across different programs. |
| 4 | Submit a role update or delivery board movement. | Program signal is captured for the active cycle. |
| 5 | Review Guided Plans. | User understands what the program and their role should do next. |
| 6 | Use Studio for a work product. | User generates or refines an artifact grounded in program context. |
| 7 | Review Client Portal only when responsible for client-facing updates. | User understands the difference between internal working signal and client-safe executive communication. |
| 8 | Escalate access, role, or quality issues to Admin. | Admin can correct assignments, review audit history, and govern quality. |

## Daily Operating Rhythm

### For Team Members

1. Open Program Hub.
2. Select the active program.
3. Set or confirm your focus role.
4. Review the program cockpit for health, current phase, milestone, top risk, next decision, and leadership signal.
5. Update your role lane only when something meaningful changed.
6. Add or update delivery board cards for your work.
7. Attach evidence when a card, decision, or risk needs supporting context.
8. Review Guided Plans for your role-specific next actions.
9. Use Studio when you need a work product for your role.

### For Delivery Leads

1. Review the cockpit at the start of the week.
2. Confirm role coverage and missing updates.
3. Review delivery board movement by role and status.
4. Check open risks, blocked cards, and decisions needed.
5. Save the weekly synthesis when the program picture changes.
6. Review Guided Plans after updates are saved.
7. Use Studio to generate or refine artifacts needed for execution.
8. Route leadership feedback or client decisions when needed.

### For Leaders

1. Open Leadership.
2. Select the program that needs review.
3. Review the executive summary, latest posture, progress, risks, and decisions.
4. Enter concise guidance for the next cycle.
5. Save the leadership review.
6. NorthStar uses that signal to refresh guidance for the delivery team.

### For Admins

1. Open Admin.
2. Review user access, program role assignments, and invitation status.
3. Review flagged guidance and audit events.
4. Monitor cost, model settings, platform health, and integration status.
5. Keep permissions and trust controls current as alpha usage expands.

## Program Hub

Program Hub is the operating cockpit for program setup and active execution. It has two paths:

| Path | Purpose | Best time to use |
|---|---|---|
| Set Up New Program | Create the program record, upload source context, define roles, and start the first guidance loop. | When a program is new or not yet captured in NorthStar. |
| Manage Active Program | Track execution, role updates, delivery cards, risks, decisions, evidence, and weekly movement. | During active delivery. |

### Set Up New Program

Use this path to establish the program foundation. Capture the program name, client or initiative context, current phase, original North Star, stakeholder temperature, delivery health, team roles, and source artifacts.

Good setup input should answer:

- What outcome is the team trying to protect?
- What are the current constraints, risks, and decisions?
- What source documents should influence guidance?
- Which roles are part of this program?
- What does leadership or the client need to see?

### Manage Active Program

Use this path for daily or weekly execution. The page is designed around three main jobs:

- View program progress in the cockpit.
- Update role-specific signal.
- Manage delivery actions and artifacts.

The cockpit gives a top-line view of health, phase progress, current milestone, top risk, next decision, and latest leadership signal.

### Client-Facing Updates

Client-facing updates are intentionally separate from internal role updates. Use the client update area only for information that is safe, polished, and appropriate for the client or executive sponsor to see.

This split matters because internal program updates may include tactical working notes, sensitive stakeholder context, relationship concerns, or candid delivery risks that help the team execute but should not be exposed verbatim to a client.

Client-facing updates should be:

- concise and executive-level
- factual and professionally worded
- focused on progress, decisions, risks, milestones, and next steps
- reviewed by the appropriate delivery or client lead before publishing
- free of internal-only commentary, frustration, sensitive personnel notes, or commercial/private delivery details

### Role Lanes

Role lanes help users focus on their assigned role first. A role lane should be updated when there is meaningful movement, a new blocker, a decision need, or an important change in scope, sequencing, dependencies, or stakeholder alignment.

Keep role updates concise:

- Progress: what changed since the last checkpoint?
- Changes observed: what shifted in scope, sequencing, dependencies, stakeholders, or assumptions?
- Risks and blockers: what could slow or stop the role's work?
- Decisions and support: what decision, input, or support is needed?

### Delivery Board

The delivery board tracks role-owned actions and deliverables. Use it for work that needs visibility, ownership, status, or evidence.

Status order:

| Status | Meaning |
|---|---|
| Not Started | The work is known but has not begun. |
| In Progress | The owner is actively working the item. |
| Needs Review | The item needs review, approval, refinement, or validation. |
| Blocked | The item cannot move without a decision, dependency, or support. |
| Done | The item is complete or no longer requires action. |

Each card should have a clear title, owner, due date when relevant, context, and attachments when evidence is needed. Board changes feed Guided Plans and Studio suggestions, so keep cards current.

### Attachments and Evidence

Attach artifacts when they provide proof or context for a decision, risk, milestone, deliverable, or work product. Examples include BRDs, roadmaps, requirements, user journeys, decision logs, meeting notes, process flows, data mappings, release checklists, and client-facing summaries.

## Guided Plans

Guided Plans answer: What should we do next?

Use Guided Plans after program setup, active updates, leadership feedback, board changes, or new artifacts are added. The page is built for executive scan first and drill-down second.

Review in this order:

1. Program health and progress.
2. Leadership inputs.
3. Gantt view of phases, milestones, and deadlines.
4. Team Action Plans by role.
5. Risks and decisions.
6. Inputs used and why guidance changed, only when more detail is needed.

### Team Action Plans

Team Action Plans are role-centric. Select your focus role to see the content most relevant to you first. Expand other roles only when you need adjacent context.

Use Team Action Plans to understand:

- Key focus areas.
- Action plan.
- Expected outcomes.
- Risks and mitigation strategies.
- Support or decisions needed.
- Role-level execution posture.

### Flagging Guidance

Flag guidance when it is inaccurate, missing important context, or misaligned with approved direction. Be specific. A useful flag explains what is wrong, why it matters, and what context should be considered.

Flagged guidance routes to Admin for governance review. Approved corrections can influence future guidance. Denied flags remain part of the audit history but should not steer future output.

## Studio

Studio answers: What should we create to move the work forward?

Studio generates role-specific work products from the selected program context. It uses uploaded artifacts, Guided Plans, role updates, leadership feedback, delivery board movement, meeting inputs, risks, decisions, and existing artifact history.

### How to Use Studio

1. Select a program.
2. Select your role.
3. Review recommended artifact briefs.
4. Load a brief that matches the work you need.
5. Edit the brief if the artifact needs a different scope, format, or emphasis.
6. Generate the artifact.
7. Review the generated slice.
8. Export, copy, or iterate.

### Example Artifacts by Role

| Role | Example artifacts |
|---|---|
| Product Management | Product roadmap, epic and feature breakdown, prioritization matrix, MVP scope, release readiness checklist, stakeholder decision log. |
| Business Analysis | Requirements matrix, user stories, acceptance criteria, traceability matrix, process flow inventory, gap analysis. |
| User Experience | User journey, app flow, service blueprint, usability risk log, research plan, persona or workflow summary. |
| Application Development | Technical implementation plan, release checklist, dependency map, architecture decision log, defect triage view. |
| Data Engineering | Data mapping, source-to-target matrix, data quality plan, integration inventory, reconciliation checklist. |
| Change Management | Stakeholder plan, communications plan, training readiness plan, adoption risk log, change impact summary. |
| Scrum Master | Sprint risk log, impediment tracker, ceremony plan, backlog readiness checklist, team operating rhythm. |
| Delivery Lead | Executive action plan, decision log, delivery risk register, cross-functional milestone plan, recovery plan. |

### Exports

Use export when the artifact needs to leave NorthStar or be shared in another workflow.

- DOCX: best for narrative artifacts, roadmaps, plans, and client-ready work products.
- CSV: best for matrix-style artifacts, logs, registers, and structured lists.
- Copy: best for moving content into email, slides, issue trackers, or collaboration tools.

## Leadership

Leadership is designed for concise weekly or biweekly feedback. Leaders should not need to read every internal update. They should review the summary, provide direction, and let NorthStar translate that signal into guidance.

Good leadership feedback is:

- Concise.
- Specific to posture, progress, risk, or decisions.
- Clear about tradeoffs or priorities.
- Written in plain language the delivery lead can act on.

After a leadership review is saved, guidance is refreshed so the latest leadership signal is reflected in the plan.

## Client Portal

Client Portal gives clients a polished executive view without exposing internal operating detail.

Clients should use it to review:

- Program Portfolio.
- Key progress updates and executive summary.
- Predictable journey, next steps, phases, and key activities.
- Program health.
- Percent complete by phase and program.
- Key risks.
- Client decisions needed.

Clients may have access to multiple programs. Use program toggles to view the right portfolio or program context.

### PDF Export

Use the Client Portal PDF export when a client sponsor needs to distribute a program update internally, attach it to a steering committee packet, or keep a point-in-time record of the current executive update.

Before exporting, confirm:

- the correct client and program are selected
- executive overview is client-safe
- current phase and percent complete have a clear basis
- milestones and decisions are current
- risks are written in a constructive, professional tone

## Admin

Admin is the control layer for trust, operations, access, and cost.

Admins use it to:

- Invite users and manage credentials.
- Assign user types and program roles.
- Add or remove program role assignments.
- Review disputed guidance and governance decisions.
- Review audit history.
- Export filtered audit events.
- Manage model settings.
- Monitor cost, usage, platform health, and integration status.

### Audit History

Audit history is compressed by default so Admins can focus on important events first. Use category chips, search, program, actor, event, and date filters to find specific activity. Expand a row only when you need metadata.

Important events include invites, access changes, model setting changes, guidance refreshes, leadership feedback, client decisions, and flags.

### Trust and Operations

Use Trust and Operations to confirm:

- Which user types have access to which surfaces.
- Whether key systems are connected and healthy.
- Whether exports, flags, client decisions, and settings changes are being audited.
- Whether cost and usage tracking are available.

### Knowledge Management Stewardship

Admins should treat NorthStar documentation as part of the product, not a side file. As features change, the knowledge base should be refreshed so users can find accurate instructions without asking the implementation team.

Until the in-app knowledge portal is built, maintain the following source documents:

- `docs/northstar-team-user-guide.md`

- `docs/northstar-project-map.md`

## Recommended Weekly Team Routine

| Day or moment | Owner | NorthStar action |
|---|---|---|
| Start of week | Delivery Lead | Review cockpit, risks, decisions, role coverage, and board status. |
| During the week | Team Members | Update role lanes and delivery cards when meaningful movement happens. |
| Midweek checkpoint | Delivery Lead | Check blocked or Needs Review cards and route decisions. |
| Leadership checkpoint | Leadership | Save concise feedback on posture, progress, risk, and priorities. |
| Before client readout | Delivery Lead or Client Lead | Review Client Portal and confirm risks, decisions, and progress are current. |
| End of week | Delivery Lead | Save synthesis, review Guided Plans, and identify next-cycle artifacts in Studio. |

## Best Practices

- Keep updates factual and current.
- Use role lanes for role-specific movement, not general notes.
- Use delivery board cards for accountable work.
- Attach evidence when it supports a risk, decision, deliverable, or milestone.
- Review Guided Plans after meaningful changes are saved.
- Use Studio to create work products, not just status summaries.
- Flag guidance only when you can provide clarifying context.
- Keep client-facing information concise and executive level.
- Admins should review audit and access regularly during alpha testing.

## Common Issues

| Issue | What to do |
|---|---|
| I cannot log in. | Confirm you are using the email address from your invitation as your username. Use reset access if needed. |
| My setup link is expired. | Ask an Admin to remove and resend the invitation, or use the recovery flow if your account is already active. |
| I do not see a program. | Ask an Admin to confirm your user type and program role assignment. |
| My role is not available. | Ask an Admin or Delivery Lead to add the role to the program. Adding a role should refresh guidance. |
| Guidance seems outdated. | Confirm the latest program updates, leadership feedback, delivery board movement, and artifacts were saved. |
| A recommendation looks wrong. | Flag the specific guidance and provide the missing or corrected context. |
| An export is missing detail. | Reopen the artifact, refine the brief, regenerate, then export again. |
| I only see Log Out in Client Portal. | Your user type may only have client access. Ask an Admin if your access needs to change. |

## Simple Rule

If something meaningful changed in the program, capture it in NorthStar. The better the signal, the better the guidance, artifacts, leadership view, and client-ready story.
